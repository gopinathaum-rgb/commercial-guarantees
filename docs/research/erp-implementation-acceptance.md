# When Is an ERP Implementation Actually Complete?

A recurring commercial question in enterprise software implementation is deceptively simple:

> **When can both the implementation vendor and customer objectively agree that an ERP milestone is complete?**

A production date by itself may not answer the question.

A vendor may consider a deployment complete because the system is in production. A customer may consider it incomplete because required business processes, acceptance tests, integrations, or production verification remain outstanding.

The important question is not who is right after the disagreement.

It is:

> **What evidence was agreed in advance that would establish completion?**

## A useful commitment structure

A bounded implementation milestone can be described as:

**Commitment → Completion condition → Evidence → Verification → Consequence**

For example:

- **Commitment:** production deployment by a fixed date
- **Completion condition:** deployment completed and mandatory acceptance tests pass
- **Evidence:** deployment record, production verification, test results
- **Verification:** an agreed person or process determines whether the evidence satisfies the condition
- **Consequence:** a predefined commercial response if completion cannot be demonstrated

This is deliberately narrower than guaranteeing that an entire ERP project will succeed.

## Questions worth asking on a real project

- What exactly does "go-live complete" mean?
- Which acceptance tests are mandatory?
- What evidence proves each condition?
- Who has authority to determine whether the evidence is sufficient?
- What happens if the evidence is incomplete?
- Does a milestone payment depend on the determination?
- Can the decision be reconstructed later from the records that existed at the time?

These questions are the subject of the current Commercial Guarantees research.

## Can You Prove It?

If you have a real implementation milestone that became difficult to establish, the useful artifact is not a hypothetical example.

A **redacted real commitment or acceptance clause** is much more informative.

The current research workflow is a private, manual one-page audit:

**Commitment → Completion condition → Evidence → Verification → Commercial consequence → Reconstruction**

No confidential customer information is required.
