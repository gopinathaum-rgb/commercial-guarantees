# Recon — Now and Destination

Date: 2026-10-01
Status: Operating framework

Recon is deliberately maintained in two parallel views:

1. **Recon Now** — what is executable and defensible today.
2. **Recon Destination** — the capability we are investigating toward.

The destination is not a feature backlog. Real commercial situations decide which parts of it become real.

## Recon Now

The current executable instrument is:

```
Sources
  ↓
Observations
  ↓
States
  ↓
Changes
  ↓
Trajectory
  ↓
Investigation
```

The v0.2 extension adds:

```
Situation discovery
  ↓
Organization resolution
  ↓
Actor / role resolution
  ↓
Public evidence / conversation surfaces
  ↓
Observation
  ↓
Situation update
```

Its immediate purpose is to help a human operator:

- preserve provenance;
- distinguish observation from inference;
- retain uncertainty;
- compare changes over time;
- reconstruct a bounded commercial situation;
- identify where human attention is justified.

This is the Recon we can operate today.

## Recon Destination

The longer-term capability is intentionally described at the level of capability, not implementation.

```
Discover situation
  ↓
Resolve commercial context
  ↓
Observe evidence and change
  ↓
Reconstruct the transaction
  ↓
Identify the economic state
  ↓
Locate the recognition boundary
  ↓
Identify where intervention may matter
  ↓
Observe the outcome
  ↓
Learn
```

The deeper research question is:

> **Can Recon understand enough of a consequential commercial situation to identify where economic reality is changing, what remains uncertain, and where human intervention may change the outcome?**

This does **not** mean Recon should become an autonomous prospecting, prediction, outreach, or decision-making system.

Human judgment remains necessary wherever identity, authority, contested claims, material economic state, or commercial consequence is uncertain.

## The bridge

The bridge between Now and Destination is not additional architecture.

It is real commercial work:

```
Real situation
  ↓
Recon Now
  ↓
Observed gap / uncertainty
  ↓
Human intervention
  ↓
Economic outcome
  ↓
Measured consequence
  ↓
Repeated mechanism
  ↓
Capability earned into Recon
```

A destination capability should move toward the executable system only when real work demonstrates that it is repeatedly necessary and economically consequential.

## Build rule

- one occurrence → observe
- two → compare
- repeated → understand the mechanism
- repeated + consequential → standardize
- repeated + measurable value → build
- repeated network dependency → investigate network position

Therefore:

> **The destination is visible. The path is empirical.**

We do not build the imagined Recon because it is intellectually attractive. We build it when reality repeatedly demands the capability.

## Data boundary

Recon continues to use the existing data classes as the canonical structure for learning from real situations.

We do not create a parallel commercial schema merely because the commercial phase has begun.

The operating loop remains:

```
real transaction
  ↓
structured data
  ↓
comparison
  ↓
repeated pattern
  ↓
standardization
  ↓
software
```

New structure is earned by a real transaction that requires it.

## Public / private boundary

The public repository can explain:

- the problem being investigated;
- the broad Recon purpose;
- the research method;
- documented evidence and research findings;
- validated boundaries and non-claims.

The public repository should **not** be treated as the complete operating specification.

The following remain deliberately private or implementation-specific:

- customer-specific evidence and commercial cases;
- internal operator procedures;
- proprietary heuristics and decision rules;
- unpublished datasets and normalized records;
- internal economic measurements;
- detailed acquisition and engagement playbooks;
- implementation details whose value depends on operational execution;
- future capabilities before real evidence justifies publishing them.

The principle is:

> **Open research where openness creates trust. Protect operational advantage where copying the description would not reproduce the capability.**

A copied diagram is not the system.

The defensible asset is the accumulation of:

```
real situations
→ evidence
→ reconstruction
→ operator judgment
→ economic outcomes
→ repeated mechanisms
→ proprietary learning
```

## Current commercial test

Recon is not validated by how sophisticated its architecture becomes.

The next meaningful test is whether Recon helps us process a real consequential commercial situation and identify an intervention that changes an economically meaningful outcome.

That outcome may be:

- payment released sooner;
- acceptance established;
- exposure reduced;
- execution resumed;
- a dispute clarified;
- working capital unlocked;
- loss prevented;
- or another measurable commercial transition.

Only real outcomes determine what Recon becomes next.
